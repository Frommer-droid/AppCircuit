# Разработка AppCircuit

## Назначение

AppCircuit — Windows desktop-приложение на Python 3.12 и PySide6. Оно
хранит сессии из программ, файлов и пауз, выполняет включённые шаги по порядку
и создаёт автономный EXE для выбранной сессии.

Версия хранится только в корневом `VERSION`. Код, package metadata, PyInstaller,
runtime manifest и установщик читают один источник версии.
Собственный код распространяется по MIT (`LICENSE`); сторонние компоненты
сохраняют свои лицензии (`THIRD_PARTY_NOTICES.md`).

## Архитектура

- `AppCircuit.py` — тонкий launcher, вызывающий `app.main.main`.
- `app/main.py` — локаль, логирование, AppUserModelID, `QApplication`, тема и окно.
- `app/core/app_config.py` — runtime-пути, имя, версия и ресурсы.
- `app/core/application.py` — сценарии приложения и маршрутизация действий.
- `app/core/session_transfer.py` — версия формата и проверка JSON импорта/экспорта.
- `app/core/session_executable.py` — снимок выбранной сессии и создание одного EXE.
- `app/core/settings_store.py` — нормализация и атомарное сохранение настроек.
- `app/models/application_entry.py` — сериализуемая запись приложения.
- `app/services/process_service.py` — сопоставление полных путей активных
  процессов с PID через WinAPI, запуск `.exe` и точечная остановка через
  `taskkill`.
- `app/ui/file_dialog.py` — постоянный файловый диалог, боковая панель и модель
  дополнительного столбца даты создания.
- `app/ui/main_window.py` — список, Qt signals, UI-обработчики и рабочий `QThread`.
- `app/ui/styles.py` — единая QSS-тема.
- `app/utils/logging_utils.py` — новый лог на каждую сессию.
- `Build_Tools/SessionRunner.cs` — автономный Windows-запускатель без консоли и Python.

UI не выполняет операции ОС напрямую. Долгие групповые действия идут через
`ApplicationCore` и `ProcessService` в рабочем потоке.

## Интерфейс

Левая панель показывает сессии: подсветка выбирает сессию для редактирования и
создания отдельного EXE, а галочки задают состав экспорта. Правая панель
показывает шаги выбранной сессии в порядке исполнения. У каждого шага есть
галочка включения и допустимое действие; кнопки под списком добавляют,
удаляют и перемещают шаги. Пауза хранит длительность вместо пути к файлу.

Для новой записи отображаемое имя формируется из имени родительской папки
исполняемого файла; подчёркивания заменяются пробелами. Ручное переименование
после добавления сохраняется.

Добавление программ и файлов выполняется через `PersistentFileDialog`: подтверждение текущего
выбора передаёт пути в накопительный список, но не закрывает диалог. Это позволяет
переходить между папками в одной сессии; закрытие окна завершает добавление.
Диалог принудительно использует Qt-реализацию (`DontUseNativeDialog`), поскольку
закрытием нативного диалога управляет операционная система. Кнопка отмены скрыта,
а `Esc` игнорируется, поэтому сессию завершает только крестик окна.
Боковая панель формируется из рабочего стола (`QStandardPaths`), системного пункта
«Мой компьютер», готовых смонтированных томов (`QStorageInfo`), домашней папки и
пяти последних каталогов, из которых выбирались программы или файлы. Последние каталоги
хранятся в `recent_application_directories`, поднимаются наверх при повторном
использовании и нормализуются с удалением дублей и несуществующих путей.
По умолчанию показаны все файлы; фильтр `.exe` остаётся доступен. Запись `.exe`
получает действия «Запустить» и «Остановить», а прочий файл — «Открыть».
При применении сессии шаги выполняются в порядке списка, включая паузы.
Галочки списка сессий сохраняются в `export_selected` каждой сессии и определяют
состав экспорта. В JSON-файле только `format`, `version` и выбранные `sessions`;
`export_selected`, геометрия окна и другие настройки не экспортируются. Импорт
проверяет все шаги до записи в `settings.json`, заменяет сессии с совпадающими
именами без учёта регистра, остальные добавляет. При замене сохраняются локальные
ID сессии и галочка экспорта; ID шагов создаются заново. Дубли имён в файле или
несколько локальных сессий с совпавшим именем считаются ошибкой, запись не меняется.
Пути к программам и файлам остаются абсолютными,
поэтому на другом компьютере их может потребоваться добавить заново.
Кнопка «Создать EXE» использует подсвеченную сессию независимо от галочки экспорта.
Она копирует готовый `assets/runner/AppCircuitSession.exe` в выбранное место и
добавляет в конец файла снимок включённых шагов. Полученный EXE выполняет шаги
по порядку без окна AppCircuit: запуск, остановку, открытие файла и паузу.
Изменение исходной сессии не меняет созданный EXE. Для обновления его нужно
создать повторно. Ошибки показываются в отдельном окне и записываются в
`%LOCALAPPDATA%\AppCircuit\SessionLaunchers\errors.log`.
Запускатель использует .NET Framework целевой системы; Python и каталог
AppCircuit для его работы не нужны. Пути к файлам остаются абсолютными.
Файлы открываются через `QDesktopServices.openUrl(QUrl.fromLocalFile(...))`
в назначенном системой приложении; операция возвращает результат передачи файла
системе, а не ждёт закрытия открывшегося приложения. Старые записи не-`.exe`
нормализуются в действие `open` при загрузке настроек.
`CreationDateProxyModel`, установленная через `QFileDialog.setProxyModel()`,
добавляет к стандартной таблице отдельный столбец «Дата создания» на основе
`QFileInfo.birthTime()`; исходные столбцы и файловая навигация остаются штатными.

## Runtime-файлы

В исходном режиме файлы создаются в корне проекта, в frozen-режиме — рядом с
`AppCircuit.exe`:

- `settings.json` — список приложений и геометрия окна;
- `application.log` — подробный лог текущей сессии.

Обязательные ключи настроек:

- `applications` — записи `id`, `name`, `path`, `process_name`, `enabled`;
- `sessions` — сессии с `id`, `name`, шагами `applications` и локальной галочкой
  `export_selected` (по умолчанию `false` для прежних настроек);
- `window_pos_x`, `window_pos_y`;
- `window_width`, `window_height`;
- `window_geometry` — Qt Base64-геометрия;
- `maximized`;
- `recent_application_directories` — до пяти последних папок выбора программ и файлов.
- `ui_scale_mode`, `ui_scale_delta_percent`, `ui_scale_percent` — автоматический
  масштаб экрана, ручная поправка от −50% до +50% и рассчитанный итоговый
  процент. При выборе значения интерфейс и сохранённая геометрия окна
  обновляются сразу; повторное применение масштаба всегда рассчитывается от
  исходного шрифта, без накопления.

В чистой конфигурации `applications` — пустой список, а `window_width` имеет
значение `null`. Это служебный признак первого запуска: окно получает ширину из
`sizeHint()` панели кнопок и горизонтальных отступов центрального layout.
Сохранённая ширина или Qt-геометрия существующей установки имеют приоритет, но
ограничиваются вычисленной минимальной шириной, если панель станет шире.

Повреждённый JSON не блокирует запуск: используются нормализованные значения по
умолчанию. `settings.json` и лог исключены из Git и release-поставки.

Если новый `settings.json` ещё отсутствует, `ApplicationCore` передаёт в
`SettingsStore` соседние каталоги прежней установки. Первый найденный файл
нормализуется и атомарно сохраняется в каталоге AppCircuit. После успешной
миграции дальнейшая работа не зависит от старой папки.

Перед групповым запуском или остановкой `ProcessService` один раз перечисляет
процессы через `CreateToolhelp32Snapshot` и получает их полные пути через
`QueryFullProcessImageNameW`. Результат хранится как соответствие нормализованного
пути набору PID.

При запуске уже работающий `.exe` с тем же полным путём и повтор этого пути
внутри одной партии попадают в `ActionReport.skipped`; portable-копии с
одинаковым именем в разных каталогах запускаются независимо. При остановке для
PID только выбранного пути вызывается `taskkill /PID ... /F /T`, поэтому
завершается конкретная portable-копия вместе с дочерними процессами, а
одноимённые копии из других каталогов остаются работать. Ошибка перечисления
процессов блокирует операцию.

Поле `process_name` сохраняется в `settings.json` для совместимости с прежними
настройками, но запуск и остановка идентифицируют приложение по полному пути.

## Автономный запускатель сессий

Исходник `Build_Tools/SessionRunner.cs` собирается в Windows EXE без консоли.
После изменения исходника обновите шаблон командой из корня проекта:

```powershell
& 'C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe' /nologo /target:winexe /platform:x64 /optimize+ /r:System.Windows.Forms.dll /win32icon:logo.ico /out:assets\runner\AppCircuitSession.exe Build_Tools\SessionRunner.cs
```

`AppCircuit.spec` проверяет наличие шаблона и включает его в `assets`.
Формат дописываемых данных определён совместно в `session_executable.py` и
`SessionRunner.cs`: версия `ACS1DATA`, UTF-8 строки с длиной, код и длительность
каждого шага, затем длина блока и конечный маркер `APPcircuit-SESS!`.
Смена этого формата требует синхронного изменения обеих сторон и тестов.

## Окружение

Используется только проектная `.venv`:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -e ".[dev]"
.\.venv\Scripts\python.exe -c "import sys; print(sys.executable)"
.\.venv\Scripts\pythonw.exe .\AppCircuit.py
```

`.vscode/settings.json` указывает на `.venv\Scripts\python.exe`. В dev extras
входят pytest, Ruff и PyInstaller.

```powershell
.\.venv\Scripts\python.exe -m ruff check .
.\.venv\Scripts\python.exe -m pytest
```

Scanner 2.x поддерживаемый источник зависимостей.

## PyInstaller onedir

Штатный spec: `Build_Tools/AppCircuit.spec`.

Перед сборкой отдельно проверить точный путь старой корневой папки `AppCircuit`
и убрать её, сохранив нужные пользовательские настройки. Затем:

```powershell
.\.venv\Scripts\python.exe -m PyInstaller `
  ".\Build_Tools\AppCircuit.spec" `
  --clean --noconfirm `
  --distpath ".\Build_Tools\dist" `
  --workpath ".\Build_Tools\build"
.\.venv\Scripts\python.exe .\Build_Tools\post_build.py
```

Альтернативный GUI-flow:

```powershell
.\.venv\Scripts\pythonw.exe .\Build_Tools\SpecCompiler.pyw
```

GUI-сборщик сам использует проектную `.venv`, удаляет предыдущую корневую
сборку, запускает PyInstaller и затем `post_build.py`. Он не запускает итоговый
exe.

`post_build.py`:

- переносит `Build_Tools/dist/AppCircuit` в корень проекта;
- копирует версию, иконку и legal/runtime bundle;
- создаёт `RUNTIME_MANIFEST.json`;
- фиксирует версии Python, PySide6, Shiboken6 и PyInstaller;
- сканирует Qt DLL и каталоги плагинов;
- удаляет временные `build/dist`.

Перед анализом зависимостей spec-файл заменяет `PATH` минимальным списком
каталогов PySide6, Shiboken, проектного Python и `System32`. Это не позволяет
внешним инструментам из пользовательского `PATH` подменить системные DLL.
Например, чужая `icuuc.dll` из Poppler приводит к ошибке Windows 127 при
импорте `PySide6.QtCore`/`QtGui` в собранном приложении. После анализа
spec-файл прерывает сборку при бинарнике вне проекта, выбранного Python/PySide
и каталога Windows. Корневой комплект MSVC runtime берётся целиком из PySide6.

## Windows-установщик

Требуется Inno Setup 6. Сначала должна существовать свежая корневая папка
`AppCircuit/`.

```powershell
.\.venv\Scripts\pythonw.exe .\00_CrRel_setup.pyw
```

Скрипт находит `ISCC.exe` через env, PATH и стандартные machine/user paths,
копирует release во временный каталог, удаляет пользовательский runtime-шум и
создаёт на настоящем Windows Desktop файл:

```text
AppCircuit_vX.Y.Z_Setup.exe
```

Политика установки:

- `D:\Apps\AppCircuit`;
- первый доступный fixed drive кроме `C:`, если `D:` отсутствует;
- `C:\Apps\AppCircuit`, если дополнительного диска нет;
- `UsePreviousAppDir=no`;
- установка x64 с правами администратора;
- полное удаление `{app}` при деинсталляции;
- отмеченная по умолчанию postinstall-галочка запуска.

Builder не запускает установщик и приложение самостоятельно.

## Portable-перенос

```powershell
.\.venv\Scripts\pythonw.exe .\00_Move.pyw
```

`00_Move.pyw` копирует свежую корневую сборку в
`D:\Portable_soft\AppCircuit`. Перед заменой проверяется абсолютный target;
завершается только процесс из целевой папки. `settings.json` сохраняется из
текущей portable-папки, а при первом ребрендинговом переносе — из соседней
папки прежней версии. После копирования приложение не запускается.
Portable-архивы автоматически не создаются.

## Release bundle

В корень onedir и установщик входят:

- `VERSION`, `logo.ico`, `RUNTIME_MANIFEST.json`;
- `LICENSE`, `EULA.md`;
- `THIRD_PARTY_NOTICES.md`, `SOURCE_CODE_ACCESS.md`;
- `QT_PYSIDE6_COMPLIANCE.md`;
- `LGPL-3.0.txt`, `GPL-3.0.txt`.

Перед внешним коммерческим релизом нужно повторно проверить фактические Qt
модули и применимые условия лицензирования. Секреты, кеши, логи и пользовательские
настройки в поставку не включаются.

## Границы release workflow

- Подготовка файлов, сборка, установщик и portable-перенос — отдельные этапы.
- Сборочные скрипты не запускают готовое приложение.
- Архив `.zip/.7z/.rar` создаётся только по отдельному запросу.
- Commit, tag, GitHub Release, orphan push и deploy не выполняются без явной
  команды пользователя.
